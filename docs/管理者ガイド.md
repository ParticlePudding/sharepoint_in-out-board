# 座席表 管理者ガイド

SharePoint への設置、社員データ・グループの管理、サイネージ（表示用PC）の運用、トラブル対応をまとめたガイドです。

- 利用者向けの操作説明 → [利用者ガイド.html](利用者ガイド.html)
- データの持ち方の詳細 → [データ構造.md](データ構造.md)
- プログラムの修正 → [開発者ガイド.md](開発者ガイド.md)

---

## 1. しくみの概要

```
 ┌──────────────── SharePoint サイト ────────────────┐
 │  サイトのアセット（SiteAssets）                     │
 │    └ 座席表アプリのファイル（index.html, *.js …）   │
 │  リスト「社員名簿」    … 1人1行。ステータス・備考など │
 │  リスト「AppSettings」 … 人数表のグループ設定        │
 └───────────────────────────────────────────────────┘
        ▲ 読み書き（SharePoint REST API・本人の権限で）
        │
  利用者のPC・スマホのブラウザ ／ サイネージPC（?signage=1）
```

- サーバー側のプログラムはありません。ブラウザが SharePoint のリストを直接読み書きします。
- 通信は**利用者本人の SharePoint 権限**で行われます。アクセス制御は SharePoint の権限設定で行ってください（画面側では制限していません）。
- 外部サイト（CDN など）からは何も読み込みません。

## 2. 初回セットアップ

### 2-1. リストを作る

**① 社員名簿**（リスト名は `社員名簿`）

| 列の表示名 | 内部名 | 種類 | 備考 |
|---|---|---|---|
| タイトル | `Title` | 1行テキスト（既定の列） | 名前 |
| 部署 | `Dept` | 1行テキスト | |
| 席番号 | `Seat` | 1行テキスト | 複数席は「, 」区切り |
| ステータス | `Status` | 1行テキスト | 選択肢列にする場合は9種類すべてを登録し、必須にしない |
| 備考 | `Remarks` | 1行テキスト | 16文字まで |
| 表示順 | `SortNo` | 数値 | |
| よく使う備考 | `QuickNotes` | **複数行テキスト（プレーンテキスト）** | 1行テキストは255文字で切れるため |
| 次回予約 | `NextSchedule` | **複数行テキスト（プレーンテキスト）** | 同上 |

> **内部名に注意**：列を作るときは、最初に**英字の内部名**（`Dept` など）で作成してから、表示名を日本語に変更してください。日本語名で作ると内部名が `_x90e8__x7f72_` のようになり、アプリから読めません。

**② AppSettings**（リスト名は `AppSettings`）

| 列 | 内部名 | 種類 |
|---|---|---|
| タイトル | `Title` | 1行テキスト（既定の列） |
| 値 | `Value` | **複数行テキスト（プレーンテキスト）** |

行は手で作る必要はありません。人数表の「グループ設定」で初めて保存したときに、自動で1行（`Title = StatsGroups`）作られます。

列の詳しい意味は [データ構造.md](データ構造.md) を参照してください。

### 2-2. 権限を設定する

| 対象 | 利用者 | 管理者 |
|---|---|---|
| 社員名簿 | **編集**（ステータス・備考・予約を書き込むため） | 編集（追加・削除を含む） |
| AppSettings | 閲覧（グループ設定を変えない人）／編集（変える人） | 編集 |
| アプリのファイル（SiteAssets） | 閲覧 | 編集 |

- 利用者は社員名簿の**他人の行も編集できる**必要があります（不在者の代理入力のため）。
- 社員の追加・削除を管理者だけに限りたい場合は、利用者の権限を「アイテムの追加・削除なし」のカスタム権限にしてください。画面の「設定」は誰でも開けますが、権限がなければ保存時にエラーになります。

### 2-3. ファイルを置く

配布フォルダの中身は次のとおりです。

```
動静表Webアプリ/
├ index.html            画面（ここだけ一番上）
├ css/styles.css        見た目
├ js/                   プログラム（config.js など13本）
├ img/
│ ├ icon/               アプリのアイコン（タブ・ホーム画面）
│ ├ floor/              フロアの見取り図（サンプル：1f.svg 2f.svg 3f.svg）
│ └ dept/               部署マークの画像（サンプル）
├ docs/                 資料
├ tools/                開発用（SharePoint には置かない）
│ └ seed.js             実リストへのテストデータ投入
├ THIRD_PARTY_NOTICES.txt
└ README.md             概要（GitHub のトップに表示）
```

SharePoint の**サイトのアセット**（`SiteAssets`）に、フォルダ（例：`seatmap`）を作って次のファイルを**フォルダ構成のまま**置きます（`index.html` から見た相対パスで読み込むため、フォルダ名を変えないでください）。

| 置くもの | 内容 |
|---|---|
| `index.html` | 画面（※ 2-4 を参照） |
| `css/` | 見た目（`styles.css`） |
| `js/`（`sample-data.js` を除く） | プログラム一式 |
| `img/icon/` | アプリのアイコン |
| `img/floor/` | フロアの見取り図。自分の職場の画像に差し替え、`config.js` の `FLOORS[].image` で指定 |
| `img/dept/`（使う場合） | 部署マークの画像。`config.js` の `DEPT_SYMBOLS` で指定 |
| `THIRD_PARTY_NOTICES.txt` | アイコン（Lucide）のライセンス表記。**必ず一緒に置く** |
| `docs/利用者ガイド.html`（任意） | 利用者に案内するとき用 |

**置かないもの**

| ファイル | 理由 |
|---|---|
| `js/sample-data.js` | テスト用の架空データ |
| `tools/` | 開発用（テストデータ投入） |
| `README.md` `docs/*.md` | 開発用の資料 |

**本番では `index.html` の次の1行を削除してください。**

```html
<script src="js/sample-data.js"></script>
```

### 2-4. `.html` が開けない場合

SharePoint Online の既定の設定では、ライブラリに置いた `.html` ファイルが**画面として開かずにダウンロード**されることがあります。その場合は次のどちらかで対応してください（テナントの設定によって可否が変わるため、SharePoint 管理者に確認してください）。

- `index.html` を `index.aspx` に名前を変えて置く。
- SharePoint 管理者に、そのサイトでのカスタムスクリプトの許可を依頼する。

### 2-5. 接続先の確認

- 通常は、置いた場所から SharePoint サイトの URL を自動で判定します（`/SiteAssets/` などより前の部分）。
- うまく判定できない場合は、`config.js` の先頭にある `SITE_URL_OVERRIDE` にサイトの URL を書いてください。

```js
const SITE_URL_OVERRIDE = "https://contoso.sharepoint.com/sites/team";
```

- URL に `?mock=1` があるときだけ**テストデータで動きます**（SharePoint には書き込みません）。本番の URL にこれらが付いていないことを確認してください。

### 2-6. 動作確認

1. ブラウザで `https://（サイト）/SiteAssets/seatmap/index.html`（または `.aspx`）を開く。
2. 座席表にカードが並ぶことを確認。
3. 自分のカードを押してステータスを変え、リスト「社員名簿」の該当行が変わることを確認。
4. 人数表 → グループ設定でグループを1つ作って保存し、リスト「AppSettings」に行ができることを確認。

## 3. 社員データの管理（画面の「設定」）

左のメニュー（スマホは下）の **設定** から開きます。

### 追加
「新規メンバー登録」に **No.（表示順）・席番号・名前・部署** を入れて登録します。新しい人のステータスは「退勤」、よく使う備考は初期の定型文になります。

### 編集
一覧の行を直接書き換えて **保存** を押します。

- 書き換えて保存していない行は黄色になります。閉じようとすると確認が出ます。
- 一覧は検索欄（No.・席番号・名前・部署）と見出しの並び替えで探せます。

### 削除
行の **削除** を押します。元に戻せません。削除した人は、次にグループ設定を保存したときにグループから自動で外れます。

### 席番号のルール
- フリーアドレスの場合は、利用者が座席表の空席から自分で席を選べます（`SEAT_ASSIGN_ENABLED`。利用者ガイド7章）。設定画面で席番号を入れておく必要はありません。
- `config.js` に登録されている席番号（例：`1F-A01`）を入れます。
- 1人で複数の席を使う場合は、`1F-A01, 3F-A06` のように区切ります（区切りは「,」「、」「/」空白のどれでも可）。
- 全角・半角、大文字・小文字は自動でそろえます。
- 座席表にない席、他の人と重複する席を入れると、保存前に確認が出ます（そのまま保存も可能）。
- 席番号が空、または座席表にない席の人は、座席表には出ませんが、リストと人数表には出ます。

### 表示順（No.）
リストの並び順に使う数値です。空欄でも構いません（空欄の人は最後に並びます）。

### 直行URL
ステータス画面の **直行URLをコピー** で、その人の入力画面を直接開くURL（`…/index.html?id=12`）が取れます。本人にブックマークしてもらうと便利です。

## 4. 人数表のグループ設定

人数表の右上 **グループ設定** から開きます。保存した内容は**全員の画面に反映**されます。

| 操作 | 方法 |
|---|---|
| グループを作る | 左上にグループ名を入れて **＋ 作成** |
| 名前を変える | 一覧で選び、右の「グループ名」を書き換える |
| 並び順を変える | 一覧の ▲ ▼ |
| 削除 | 一覧の削除ボタン |
| メンバーを登録 | 右側で人を検索し、チェックを付ける／外す（「検索結果をすべて選択／解除」も可） |
| 保存 | **変更を保存（全ユーザーに反映）** |

- 1人が複数のグループに入っても構いません。
- **同時編集の保護**：開いている間に他の管理者が先に保存していた場合、上書きせずに「他のユーザーが先に設定を更新していました」と表示されます。いったん閉じて開き直し、最新の設定に対してやり直してください。

## 5. サイネージ（表示用PC）の運用

### 役割
- 座席表を常時表示する。
- **予定予約を予約日時に反映する**（利用者のPC・スマホは反映しません）。

### 設定方法
URL の最後に `?signage=1` を付けて開きます。

```
https://（サイト）/SiteAssets/seatmap/index.html?signage=1
```

- サイネージでは「自分」ボタンなどは表示されません。
- 起動時と**15分ごと**に全件を、**1分ごと**にステータス・備考・予約だけを読み直し、そのたびに予約日時を過ぎた予約を反映します（予約時刻から1〜2分以内に反映されます）。
- 3〜4台が同時に動いても、同じ予約を二重に反映しないように作ってあります（反映直前に最新を読み直し、反映済みならスキップ）。

### 注意
- **サイネージが1台も動いていない日は、予約が反映されません**（予約は残り、同じ日のうちにサイネージが動けばそのときに反映されます。前日以前の予約は反映せずに消えます）。
- スリープ・画面オフ・ブラウザの自動終了を無効にしてください。OS の起動時にブラウザがこの URL を開くように設定しておくと安心です。
- サイネージの PC も SharePoint に**編集権限のあるアカウント**でサインインしておく必要があります。

## 6. 便利な URL の付け方

URL の最後に付けると、開いたときの表示を指定できます（`&` でつなげて複数指定可）。

| 付けるもの | 意味 | 例 |
|---|---|---|
| `?id=12` | その人のステータス画面を開く | 本人用ブックマーク |
| `?user=名前` | 名前で探して開く（部分一致） | `?user=山田` |
| `?seat=1F-A01` | その席の人を開く | 席に貼るQRコード |
| `?floor=2F` | 最初に表示するフロア | フロアごとのサイネージ |
| `?sidelist=1` | サイドリストを開いた状態で表示 | 受付用PC |
| `?signage=1` | サイネージとして動かす | 5章 |

例：2Fのサイネージでサイドリストも表示 → `index.html?signage=1&floor=2F&sidelist=1`

## 7. 設定ファイル（`js/config.js`）で変えられること

テキストエディタで開き、保存して SharePoint に上書きします。書き方を間違えると画面が表示されなくなるので、**変更前のファイルを必ず控えて**から作業してください。

| 項目 | 内容 |
|---|---|
| `LIST_NAME` / `SETTINGS_LIST_NAME` | リスト名を変えた場合 |
| `FLOORS` | フロア・見取り図の画像（`img/floor/` に置く）・席の位置（詳しくは開発者ガイド） |
| `DEPT_SYMBOLS` | 座席カード左上の部署マーク（1文字＋色、または `img/dept/` に置いた画像。16×16で表示） |
| `SEAT_ASSIGN_ENABLED` | 空席を押して席を割り当てる機能と、ステータス画面の「席の割り当て解除」（既定 `true`）。固定席で利用者に席を変えさせたくない場合は `false` |
| `DEFAULT_QUICK_NOTES` | よく使う備考の初期の定型文 |
| `NOTE_MAX` | 備考の最大文字数（既定16） |
| `QUICK_NOTES_MAX` | 1人あたりの定型文の上限（既定20） |
| `POLLING_INTERVAL_MS` | 自動更新の間隔（既定1分） |
| `SIGNAGE_FULL_REFRESH_MS` | サイネージの全件更新の間隔（既定15分） |

ステータスの種類を増やす・名前を変える場合はプログラムの修正が必要です（開発者ガイド参照）。

## 8. 更新（新しい版への差し替え）

1. 変更のあったファイルを SharePoint に上書きします。
2. 利用者には、ページの再読み込み（PCは `Ctrl` + `F5`）をお願いしてください。ブラウザが古いファイルを覚えていることがあります。
3. `index.html` に `js/sample-data.js` の行が戻っていないか確認してください。

## 9. トラブル対応

| 症状 | 確認すること |
|---|---|
| 画面が真っ白 | ブラウザの開発者ツール（F12）→ コンソールの赤いエラー。`js/config.js` の書き間違いや、`css/` `js/` フォルダの置き忘れが多い |
| 座席表の背景（見取り図）が出ない | `config.js` の `FLOORS[].image` のパス（`img/floor/…`）とファイル名が合っているか |
| `.html` がダウンロードされる | 2-4 を参照 |
| 上部に赤い帯「通信エラー」 | SharePoint にサインインしているか、リスト名・列の内部名が正しいか |
| 「保存できませんでした」が出る | 利用者に社員名簿の編集権限があるか。リストの列の種類（特に複数行テキスト）が合っているか |
| テストの名前が表示される | `index.html` から `js/sample-data.js` の行を消したか。URL に `?mock=1` が付いていないか |
| 予定予約が反映されない | サイネージが `?signage=1` で動いているか、スリープしていないか、編集権限があるか |
| 人数表が「グループ設定を読み込めませんでした」 | リスト `AppSettings` があるか、列 `Value` が複数行テキストか、閲覧権限があるか |
| 「他のユーザーが先に設定を更新していました」 | 正常な保護動作。グループ設定を閉じて開き直してから再編集 |
| 「自分」ボタンで別の人が開く | その端末で設定し直す（ステータス画面の「自分に設定」）。設定は端末ごと |
| 座席表に出ない人がいる | 席番号が空、または `config.js` にない席番号。設定画面で確認 |

### SharePoint のリストを直接編集するとき
- `Status` には9種類（出勤・会議・現場・出張・在宅・退勤・休暇・午前半休・午後半休）か空欄だけを入れてください。それ以外は「未入力」として表示されます。
- `QuickNotes`・`NextSchedule` の書式は [データ構造.md](データ構造.md) を参照してください。`NextSchedule` の書式が崩れていると、予約は「なし」として扱われます。

## 10. セキュリティ・運用上の注意

- 画面の「自分」は**本人確認ではありません**（端末に名前を覚えているだけ）。
- 席の割り当て（`SEAT_ASSIGN_ENABLED`）が有効だと、利用者は**誰の席でも**空席へ移動・解除できます（ステータスと同じく、代理入力を想定）。固定席の職場では `false` にしてください。
- 画面の確認ダイアログは操作ミス防止のためのもので、権限の制御にはなりません。権限は SharePoint で設定してください。
- テストデータ（`js/sample-data.js`）には実在の個人情報を入れないでください。
